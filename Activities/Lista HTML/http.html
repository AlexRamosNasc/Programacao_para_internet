Papel do HTTP na comunicação entre navegador e servidor

O HTTP (Hypertext Transfer Protocol) é o protocolo que funciona como o idioma padrão para a comunicação entre o navegador e o computador onde o site está guardado.

Sua função principal é reger o modelo de Requisição e Resposta:

  • Requisição (Request): Quando você digita um endereço ou clica em um link, o navegador envia um pedido em HTTP para o servidor.
  • Resposta (Response): O servidor recebe o pedido e responde com uma mensagem HTTP contendo o status da ação junto com os dados solicitados (código HTML, imagens, CSS).

Clientes, Servidorer, Requisições e Respostas

  • Cliente: O dispositivo ou aplicativo que o usuário utiliza para solicitar dados e visualizar conteúdos na tela.
  • Servidor: O computador remoto de alta capacidade que armazena os arquivos do site (HTML, imagens, bancos de dados) e aguarda pedidos de acesso para processá-los.
  • Requisição O pedido enviado pelo cliente ao servidor para obter um recurso ou enviar dados.
  • Resposta A mensagem devolvida pelo servidor ao cliente contendo os dados solicitados acompanhados de um código de status.

Métodos GET e POST

  1. GET
    • Finalidade: Utilizado para buscar ou ler informações do servidor sem alterar nenhum dado.
    • Envio de dados: Envia os parâmetros expostos diretamente na URL.
    • Uso e Segurança: Não deve ser usado para dados sensíveis. Pode ser salvo nos favoritos e armazenado em cache pelo navegador.
  2. POST
    • Finalidade: Utilizado para enviar e processar dados no servidor, como criar novos registros ou alterar o banco de dados.
    • Envio de dados: Envia os dados ocultos no corpo da requisição, sem mostrá-los na URL.
    • Uso e Segurança: Ideal para formulários de login, cadastros, senhas e envio de arquivos. Não fica salvo no histórico de navegação e não é armazenado em cache.

Exemplos de HTTP

Requisição

    "GET /historia_web.html HTTP/1.1
    Host: www.meusite.com.br
    User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
    Accept: text/html,application/xhtml+xml
    Accept-Language: pt-BR,pt;q=0.9
    Connection: keep-alive"

Linha de Requisição (Request Line): GET /historia_web.html HTTP/1.1

  • Método usado (GET).
  • Caminho do arquivo solicitado (/historia_web.html).
  • Versão do protocolo (HTTP/1.1).

Cabeçalhos (Headers): Host, User-Agent, Accept, etc.

  • Informam o servidor qual site está sendo acessado, qual o navegador/sistema operacional do usuário e quais tipos de arquivos ele aceita receber.

Corpo (Body): Vazio neste caso (requisições GET não costumam enviar corpo).

Resposta

    "HTTP/1.1 200 OK
    Date: Wed, 07 Oct 2026 20:00:00 GMT
    Server: Apache/2.4.52 (Ubuntu)
    Content-Type: text/html; charset=UTF-8
    Content-Length: 124

    <!DOCTYPE html>
    <html lang="pt-BR">
    <head>
        <title>História da Web</title>
    </head>
    <body>
        <h1>Página Carregada com Sucesso!</h1>
    </body>
    </html"

Linha de Status (Status Line): HTTP/1.1 200 OK

  • Versão do protocolo (HTTP/1.1).
  • Código e mensagem de status (200 OK = a requisição funcionou).

Cabeçalhos (Headers): Date, Server, Content-Type, Content-Length, etc.

  • Informam a data da resposta, qual servidor processou o pedido, o formato do conteúdo retornado (text/html) e o tamanho em bytes.

Corpo (Body): O código HTML da página (o conteúdo real exibido na tela do usuário).

Códigos de status

  1. 200 OK: Requisição bem-sucedida. O servidor processou o pedido com sucesso e devolveu o recurso solicitado.
  2. 301 Moved Permanently: Redirecionamento permanente. A página ou arquivo mudou definitivamente para uma nova URL.
  3. 302 Found: Redirecionamento temporário. O recurso está temporariamente em outro endereço, mas a URL original continuará sendo usada no futuro.
  4. 400 Bad Request: Requisição inválida. O servidor não conseguiu entender a solicitação devido a erros de sintaxe ou dados incorretos enviados pelo cliente.
  5. 403 Forbidden: Acesso proibido. O servidor entendeu o pedido, mas o cliente não tem permissão de acesso ao recurso solicitado.
  6. 404 Not Found: Recurso não encontrado. O servidor está no ar, mas a URL solicitada não existe ou foi movida sem aviso.
  7. 500 Internal Server Error: Erro interno do servidor. Ocorreu uma falha inesperada no código ou na configuração do próprio servidor ao tentar processar o pedido.
